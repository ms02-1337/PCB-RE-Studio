# ADR 0002: .pcbre ZIP project format

Status: accepted, 2026-11-15.
Store each project as one portable .pcbre file: a ZIP containing project.json (Deflated; schemaVersion-gated at 1; camelCase, mirrored in src-tauri/src/project/schema.rs and src/workbench/placement/projectDoc.ts) plus blobs/<sha256-hex> entries (Stored). Assets are content-addressed by SHA-256, so identical bytes are stored once however many components reference them; board images, component photos, and datasheet files share one deduplicated store.
Single-file portability is a user requirement: a reverse-engineering project with board photos, component images, and datasheets must move as one artifact between machines and backups. Considered and rejected: SQLite (opaque binary, harder to inspect or diff, still needs blob handling), a JSON folder (many files that separate on copy, no dedup), and IndexedDB (webview-local, not a user-visible artifact).
Save validates the document, garbage-collects to the referenced blob set, sources blobs from a staging cache (app cache dir pcb-re-studio/staging, cleared on startup and close, pruned after each save) or stream-copies them from the previously open container, builds the archive at a temp file, syncs, and renames over the target. project_new writes the file immediately, so an unsaved-path state never exists.
Consequences: every save rewrites the full archive; accepted at current scale because autosave debounces to one write per 2s idle and single-flights overlapping saves. Stored (uncompressed) blob entries keep writes cheap for already-compressed images and PDFs and allow raw stream copies between containers. A future incremental or chunked container can be introduced behind a new schemaVersion without breaking v1 readers.
