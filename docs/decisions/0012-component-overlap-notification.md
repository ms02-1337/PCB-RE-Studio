# 0012 — Component overlap notification

The Visual Editor notifies the user when two placed electrical components collide, without ever blocking placement or movement. A pair is flagged when the components' footprint extent boxes intersect (touching counts) or when the boxes sit within 0.5 mm of each other on the same copper layer. Notification is derived at render time from committed and in-flight placements — no document state, no persistence, no schema change — and disappears as soon as the pair separates.

Extents reuse the body hit-testing geometry (`footprintBounds`: graphics anchor points plus circumscribed pad extents) rotated, scaled and offset like pad copper, compared as world axis-aligned boxes (`componentWorldBounds`, `componentProximities` in `src/workbench/electrical/domain.ts`). These boxes are deliberately conservative: they approximate courtyards the way industry tools approximate them (bounding-box overlap checks, e.g. KiCad courtyard-collision tests via generous extents), so the proximity threshold is small to avoid flagging legitimate dense layouts. Front and back components are compared only within one layer, because stacked opposite-side parts are legal.

Surfacing is twofold. The canvas draws dashed red outlines around every involved component — including the translucent placement ghost, so a bad drop is flagged before it happens, and drag/multi-drag drafts, so feedback tracks the gesture. The component inspector shows a `role="status"` banner naming each pair, distinguishing `overlaps` from `near` with the gap in millimetres (world pixels when the PCB is uncalibrated). An earlier survey of PCBRevEng found an on-demand "Error Check" report; persistent, zero-action marking was chosen so the notification needs no user step, matching the live endpoints indicator pattern (0010-era visual editor surfaces).
