# Architecture

A local desktop application: SolidJS + TypeScript + Vite owns interaction and presentation; Rust owns native access and expensive domain operations. Keep domain algorithms independent of Tauri handlers. The workbench is in src/workbench; shared UI can grow under src/ui when reused; IPC lives in src/bridge; native integration is in src-tauri.

## Boundary contract

Custom commands (camelCase payloads from TS, snake_case params in Rust):

- app_info() → { name, version }: read-only app metadata; browser preview returns explicit preview metadata.
- project_new(path, name) → { doc, assets, path }: creates and activates a new .pcbre file immediately.
- project_open(path) → { doc, assets, path }: loads and validates an existing container.
- project_import_copy(sourcePath, destPath) → { doc, assets, path }: validates an existing .pcbre container, copies it to a new destination without replacing an existing file, validates the copied container, and activates the copy. The copy is installed atomically from a sibling temporary file; failures before activation leave the currently open project path unchanged. The UI flush-saves dirty active work before showing the source and destination pickers; cancelling either picker leaves the active project unchanged.
- project_save(doc) → { path, bytes, blobCount, savedAt }: saves the active project in place.
- project_save_as(doc, path) → { path, bytes, blobCount, savedAt }: saves to a new target and switches to it.
- project_close() → void: closes the project and clears staged assets.
- project_export_copy(doc, path) → { path, bytes, blobCount, savedAt }: saves a validated standalone copy to path without switching the active target.
- project_export_html(html, path) → bytes written: replaces @@ASSET:<sha256>.<ext>@@ tokens in the html text with base64 data: URIs streamed from staging or the open container; only HTML text crosses IPC, never image bytes. Malformed tokens → invalid_data and unresolvable hashes → missing_blob fail before the destination is touched; the write is atomic (temp file + rename).
- project_delete() → void: deletes the open container file (a missing file counts as deleted), then clears the active path and staging; IO errors keep the project open.
- asset_import(path) → { hash, size, name }: streams and SHA-256-hashes a file in Rust; asset bytes never cross JS.
- asset_import_clipboard_image() → { hash, size, name }: reads the native image clipboard with arboard, encodes PNG, and SHA-256-stages it as clipboard.png; pixels and encoded bytes stay in Rust. Requires an open project.
- asset_read(hash) → binary tauri::ipc::Response: blob bytes as a raw IPC response, never base64/JSON.
- asset_export(hash, destPath) → void: streams one blob to a user-chosen path.

All commands validate untrusted input in Rust and return structured errors { code, message, detail? }, normalized in src/bridge/project.ts; browser preview throws typed errors and disables project actions instead of faking success. Domain logic stays pure in src-tauri/src/project/*; commands.rs holds thin adapters over a Mutex<Option<open path>> and runs blocking file IO off the async executor. Document TS/Rust contracts together: they mirror in src/bridge/project.ts and src/workbench/placement/projectDoc.ts against src-tauri/src/project/schema.rs.
Clipboard reading, PNG encoding, and staging run on the blocking pool. Encoding rejects empty or inconsistent RGBA buffers, dimensions above 16384 pixels per side, and decoded data above 64 MiB (16777216 RGBA pixels). Missing or unreadable clipboard images return structured errors. The native command rechecks the open project before staging; the UI captures the target component and project session before imports and discards stale completion after project changes. The clipboard path adds the arboard and png crates; the HTML export writer adds base64. HTML reports are built purely in src/workbench/placement/htmlExport.ts and finalized by the token-substitution writer in src-tauri/src/project/html_export.rs.
Projects persist as one portable .pcbre ZIP: project.json (Deflated; schemaVersion-gated; camelCase) plus content-addressed blobs/<sha256> entries (Stored). Identical bytes are stored once however many components reference them. Save writes only referenced blobs (garbage collection), sourcing them from the app-cache staging directory (pcb-re-studio/staging, cleared on startup, close, and delete, pruned after each save) or stream-copied from the previously open container, then replaces the target atomically via temp file + rename. v1 grows additively: boards gained optional crop (image-pixel rect), rotation in degrees (finite, [0,360), written by the UI in 0.1° steps; whole degrees serialize as JSON integers so quarter-turn files stay byte-identical), flipH/flipV, scale percent, and a picture lock; components gained optional imageNames (per-image display labels keyed by asset sha256, ≤64 entries, values ≤200 chars, no blob references); the project gained an optional description. Every new field deserializes with serde defaults on both sides, so files written before these fields load unchanged and schemaVersion stays 1 (docs/decisions/0003-v1-additive-board-transforms.md, docs/decisions/0007-precise-rotation-and-image-names.md). Component shapes stay in original image pixels; board transforms apply only at render, hit-test, and export time via the fixed crop→rotation→flip→scale pipeline (src/workbench/placement/boardTransform.ts), whose generalized rotation about the crop center is exactly the legacy mapping at quarter turns.
The frameless shell uses Tauri's core window API through src/bridge/window.ts for minimize, maximize/restore, close, dragging, and maximize-state observation. The main-window capability explicitly grants those window operations, event listen/unlisten, and only the dialog plugin's allow-open and allow-save, so native path pickers can run while every byte of project and asset IO stays inside the custom commands above; no other plugin access is granted. The bridge normalizes action/state initialization failures, guards browser preview, and returns cleanup for resize observation. UI teardown releases that listener. Browser preview disables native window controls.
Tauri custom commands are available to local app content by default; plugin capability restrictions are not a substitute for validating custom command access. No remote content is loaded. Production CSP limits scripts to local sources; img-src additionally permits data: and blob: URLs for canvas and object-URL thumbnails (component images). Inline styles are allowed for framework/layout interoperability; never add unsafe-eval.
Only grant plugin permissions actually needed, scoped to windows/resources. No filesystem, shell, network, or updater plugins by default.

## Performance

Board mapping uses persisted scene tabs (`MappingTab { id, name, boardIds }`) to group image records without changing component ownership: each `Board` remains one source image and `Component.boardId` keeps its markings in that image's original pixels. Optional `mappingTabs` and `activeMappingTabId` fields extend project schema v1; optional finite `sceneX`/`sceneY` coordinates translate each image after crop → rotation → flip → scale. The store normalizes legacy files into one tab per existing image and new or empty projects into one empty tab; ungrouped image records join the first tab. `activeBoardId` selects an image within the active tab. Rust validates tab identifiers, image references, unique image ownership across tabs, and finite placement coordinates. See docs/decisions/0005-mapping-scenes.md.

Canvas rendering and hit testing cover every image in the active scene, with later images visually on top. Image movement uses a transient drag draft and commits one placement update on pointer-up, so its component shapes are never rewritten. Fit operates on whole-scene bounds. Decoded images are retained for the active scene, pending loads are deduplicated, and stale resources are released. Refdes labels are clipped to their actual component shape and omitted when too small to read; zoom does not move labels outside components. HTML export groups the same positioned images by mapping tab.

Keep high-frequency pointer/canvas state out of broad UI subscriptions. Prefer derived signals and narrow stores; virtualize large trees when introduced. Schedule blocking CPU/IO work away from UI/async executor threads; long jobs need progress, cancellation, and resource bounds. Use channels for ordered streaming and binary responses or scoped assets for bulk bytes instead of JSON/base64 images.
Project persistence and the placement canvas renderer are now selected; their requirements exist. Keep the canvas on plain Canvas 2D with a dirty-flag requestAnimationFrame loop, pointer gestures in a pure controller, and drag drafts outside the reactive store (one store write per gesture). Do not adopt heavyweight canvas/GPU libraries without measured need. PCB import/export formats beyond the .pcbre container remain unspecified until requirements and representative fixtures exist.

## Validation and releases

Use frontend tests for interaction, Rust tests for native logic, and dedicated desktop-test builds for native smoke tests. WDIO plugins must remain optional and absent from default production builds. CI builds native executables on all desktop hosts; bundling/signing/public releases are deferred.

## Visual editor

Visual editor PCB workspaces are independent of Board mapping. The optional additive v1 visualEditor document contains PCB records, physical copper-layer identities, image instances and active PCB identity. Image instances reference content-addressed assets and carry independent placement, flips, visibility, opacity and alignment locks. Physical layer assignment never changes transforms or paint order. Include visual image hashes in native save garbage collection and frontend asset-reference history safeguards. Existing import/read commands remain the native boundary.

Image transforms are non-destructive and render-time only (docs/decisions/0008-visual-image-transforms.md): `VisualImage` gained additive optional `crop` (source-px rect), `rotation` ([0,360)), `scaleX`/`scaleY`, and `warp` (2×2, set only by 4-point Align; mirrored mappings allowed); `VisualPcb` gained `pxPerMm` (world px per mm from Calibrate). All apply about the crop-rect center as `L = warp · flips · rotation · scale` followed by translation — identity reproduces legacy rendering exactly, and every new field is Option/skip-none in Rust so legacy files stay byte-identical; Rust validates all present values. The math lives in the pure `src/workbench/visual/transform.ts` and the tool state machines in the DOM-free `toolController.ts`, which emits commit intents and overlay descriptors consumed by the canvas: one store mutation per gesture (undo tracks gestures 1:1), pointer state outside the reactive store. View flips are view-only canvas mirroring that affects rendering and pointer mapping but never the document. Transforming an image that participates in an alignment warns first.

Visual copper uses optional per-PCB nets, traces, zones and through-vias in additive schema v1. Geometry and dimensions stay in PCB world pixels independently of photograph transforms; calibrated inspectors convert through pxPerMm. Logical net assignments survive disconnected geometry. Trace/via contact edits and any accepted net merges commit atomically through shared document history. Zones document manually netted planes and never automatically connect enclosed conductors. Native schema validation mirrors these frontend records.

## Electrical components and KiCad libraries

Native KiCad library commands own local source registration, variable resolution, cancellable indexing, paged search, normalized library loading and app-local component definitions. Bounded S-expression parsing accepts supported modern KiCad libraries and rejects unsupported electrical geometry explicitly. The bridge is src/bridge/kicad.ts; source paths and local definitions remain machine-local. Downloaded `.kicad_mod`/`.kicad_sym` files import (`kicad_import_files`) into a protected app-data library (`kicad-local/Imported.pretty` for footprints, `kicad-local` root for symbol files): each file is fully parsed before it is copied, identical content is deduplicated (same name with different bytes coexists under a content-hash suffix), entry identity is built by the same `index_file` helper rescans use so the local source never duplicates entries, and the source (marked `local`) cannot be redirected or removed. Placed definitions are immutable project snapshots. The container codec interns definitions by content hash and hydrates them on load, preserving runtime types and legacy schema-v1 files.

Visual PCB components carry stable numbered terminals, physical placement and optional explicit Board mapping links. Duplicate numbered pads share a terminal; NPTH holes and unnumbered pads are not electrical terminals. Copper contact includes supported pad geometry and layer membership. Schematic units, anchored wires and labels have independent positions while using the same logical nets. Component edits, remapping and conflicting connections use pending transactions and commit once after conflict resolution. No power net is inferred from an imported symbol name.

Schematic/BOM projections live in src/workbench/electrical. Export generates private KiCad 9 symbols and project-local libraries, preserves explicit net assignments with labels, and writes an atomic ZIP through Rust. Unsupported or ambiguous electrical data blocks export rather than producing lossy connectivity.

Whole-stack photograph mirroring left-composes a shared world reflection into every image warp and anchor about the bounds center of all photos. Hidden photos participate; any locked photo blocks the entire operation. One document mutation preserves registration and undo, without resampling or changing electrical geometry, calibration, layer assignments or image order.
