# Workbench design contract

Project home uses a spacious dashboard layout: larger welcome text and actions, a separated recent-project list, and an expanded project details surface with prominent board, component, asset-count, and asset-storage statistics. Autosave configuration is available through Settings rather than a dashboard action. Settings uses a compact, normal-case title header matching the main title-bar surface; its section tabs indicate selection only along the left edge. The main window title is centered against the full window width with symmetric space reserved for controls and truncation when space is limited.

Use a compact desktop-workbench layout: tab content with its own navigation and inspectors where needed, and a persistent status bar. Do not show the command palette, Projects Explorer/Search sidebar, or optional bottom Output panel. The desktop window is frameless with native resizing. A 36px custom title bar centers the app and project name, falling back to “PCB RE Studio — No project open”. Keep minimize, maximize/restore, and close at the top right; title space supports dragging and double-click maximize/restore. A Settings gear beside the theme toggle opens the in-app configuration dialog from every tab. The dialog has a left navigation rail with General and Autosave tabs and a right content panel; tab changes use keyboard navigation, focus stays inside the dialog, and closing restores focus to the invoking control. Native window controls are disabled in browser preview.
Dark is the default; support light and dark through CSS tokens in src/workbench/theme.css. Use neutral surfaces and Caterpillar-inspired yellow (#FFCD11) accents, with dark text on yellow fills and darker gold focus/selection indicators in the light theme. The title-bar theme toggle remembers the preference locally when storage is available. This preference does not introduce project persistence. System UI fonts; 13px base text; compact controls; 11px panel labels; 34px workspace tabs, 28px status bar. Central content must retain available space.
Controls need accessible names, hover, active, disabled where relevant, and visible focus states. Buttons have subtle outlines, small corner radii, stronger hover borders, and simple monochrome action icons alongside text. The root viewport does not scroll or bounce; panels retain their own scrolling with overscroll containment. Use semantic HTML and keyboard operation. The title bar contains compact File, Edit, and About menus before the theme toggle. Menus support keyboard navigation and close after selection, on outside click, and on Escape. File includes project actions and recent projects; Edit offers project details and configuration; About shows app metadata. Do not add dead buttons for future PCB features.
Immediately below the title bar, full-width workspace tabs appear in this order: Projects, Board mapping, Visual editor, Schematic, BOM, Nets. Projects is selected initially. Tabs use associated panels and roving keyboard focus with arrow keys, Home, and End; the row scrolls horizontally when needed. Panels without a tool yet keep an honest empty state, with no demo content or placeholder inspector. There is no Projects Explorer/Search sidebar, global Inspector, or optional Output panel. Projects and Board mapping stretch to fill the available workspace height; Projects content and Board mapping properties scroll internally. At the right end of the tab row, outside the tablist element, an aria-live save badge with a state-colored dot (Unsaved changes / Saving… / Saved HH:MM:SS / Save failed / Save blocked) shows the open project's save state in every tab.
The Projects tab is the project home. With a project open it shows a card with an editable name (non-empty after trim) and description (≤4000 chars), created/updated timestamps, the file path, and prominent layer, component, asset-count, and asset-storage statistics, plus actions: New project…, Open…, Save as…, Export copy…, Delete…, and Close project. Export copy saves a standalone container without switching the active target; Delete flush-saves unsaved work, requires confirmation, deletes the .pcbre file from disk, closes the project, and removes its recents entry — a declined confirm, failed flush, or failed delete keeps the project open. Without a project the tab offers New, Open, Import project, and a recent-projects list (localStorage, path-deduped, most-recent-first, capped at 10; clicking a recent entry flush-saves unsaved work first). General settings include the color theme and app version. Autosave settings (enable/disable, delay clamped 500–60000 ms) persist locally and are available in the configuration dialog under Autosave; disabled autosave marks changes unsaved but never writes automatically, and manual save is unaffected. Dialog-backed actions are disabled in browser preview. Project actions are available from File; Ctrl+S and the tab-row save badge remain available; the Board mapping action row does not repeat the project name or save status.
The Board mapping tab (formerly Component placement) hosts the component-marking tool. A header row offers Add image…, Export HTML…, Manage types…, and a filterable type combobox for new components; project lifecycle actions live in the Projects home and File menu. A vertical icon toolbar on the left edge carries the tools — Rect (R), Ellipse (E), Polygon (P), Crop (C), Select (V), Pan (H) — grouped by thin separator lines without text labels, plus Fit (0), 100% (1), and zoom ±, with shortcut titles on every button. Icon-only picture transforms (rotate 90° CCW/CW, mirror vertical/horizontal) sit directly after Crop and stay enabled only while an unlocked picture is selected. The board canvas keeps wheel zoom, pan, hover tooltips (refdes, type, part number→value fallback, marking), direction-correct move/resize cursors (rectangles and ellipses both resize from edges and bbox corners), a context menu (duplicate/lock/z-order/delete), and keyboard operation (tool keys, arrow nudging, Delete, Ctrl+D, 0/1/±, Esc clears selection). Shapes render in type colors with contrast-aware refdes labels clipped inside the actual marking shape. Labels shrink or disappear when too small to read rather than moving outside the component. With the Select tool, clicking an image selects its picture (a component hit wins), and dragging an unlocked picture moves it with its markings; the inspector's picture section then offers an editable picture name, icon-button rotate ±90°, fine rotation in 0.1° steps, mirror horizontal/vertical, scale percent, and crop apply/cancel, with lock and delete-image actions in a footer row. Picture transforms are display-only: component shapes stay in original image pixels and pass through the fixed crop→rotation→flip→scale pipeline followed by scene translation at render and hit-test; cropped-away components are not rendered or hit-testable but remain in the document, recoverable by widening the crop. The Crop tool drags a rectangle in image pixels; Apply commits it to the board, Cancel/Escape discards it. Mapping tabs sit separately below the canvas — switch, delete (confirm), and rename via double-click or F2; tabs show their name only, without an image-count subtitle. Each tab can hold several images on one canvas. A new project has one empty tab; the adjacent + creates another empty tab, while Add image… imports into the active tab. New images are placed beside existing images. Deleting the last tab leaves one empty tab. Existing projects retain one tab per former image until the user edits their scenes. A tab-local Selection details inspector collapses to a narrow restore control and resizes from its left edge by pointer dragging or keyboard arrows. It edits identification fields, status, datasheet URL and imported file, component image, and notes, with lock and duplicate controls; a modal manages component types (seeded refdes prefixes and read-only palette colors — new types get a random palette color; deletion reassigns to Unassigned). The type modals are centered in the viewport with a separated title, content, and footer. The properties inspector belongs to Board mapping and is not rendered in other tabs. Autosave runs after a configurable idle delay (500–60000 ms, default 2 s), single-flight, with the dirty/saving/saved/failed/blocked state in the tab-row badge only; Ctrl+S saves immediately and Save As switches the target. The persistent status bar never duplicates save state: it shows the canvas hover summary (component refdes, type, and part number/value/marking, or the hovered picture's name) and falls back to Ready.
Type picking uses a filterable combobox (component inspector and new-component picker): click lists all types, typing filters name and prefix case-insensitively, arrows/Enter/Escape navigate, with ARIA combobox/listbox semantics; its “+” opens a viewport-centered create-type modal that pre-fills the name from the filter text, suggests a prefix, silently picks a random default color, and enforces the type-manager validation rules — Enter confirms and selects, Escape cancels. Export HTML… writes a standalone, read-only HTML report: one self-contained file with a mapping-tab strip and positioned image scenes, CSS-transformed board pictures (crop/rotate/flip/scale) carrying an SVG shape overlay in original image coordinates so markings glue to the picture, hover tooltips, a click-open details drawer with every component field, inlined component photos, and datasheet name/URL listings (PDFs are not inlined); user strings are HTML-escaped and the file follows dark and light color schemes. Exported board tabs are mouse-only; keyboard accessibility is minimal — a known limitation. Image bytes never cross IPC: the Rust writer inlines blobs as data: URLs.
The selected component’s Image section offers Browse… for a local image and Paste image for the native image clipboard. Both actions can attach or replace the image; the photo caption holds a per-image name input and an icon-only trash button that removes the image, and clicking the thumbnail opens a large centered viewer with clamped wheel zoom and drag-pan, dismissible via Escape, backdrop, or its close button. Ctrl/Cmd+V pastes an image for an unlocked selected component while its Board mapping tab is active. Text inputs, textareas, editable content, and dialogs retain normal paste behavior; hidden tabs do not handle the shortcut. Image imports disable the controls while busy and show inline errors without replacing the existing image on failure. These native actions are disabled in browser preview.
For changes, inspect dense and narrow desktop layouts, keyboard focus, contrast, panel resizing, and overflow. Avoid rounded marketing cards and decorative animation in work surfaces.

All in-app modal overlays center their dialogs with symmetric viewport padding. Dialogs share a visible themed outer border and subtle corner radius, darker title/action surfaces, and a distinct content area with restrained separators; short windows keep dialog content scrollable. Standalone HTML reports include scene zoom out/in and 100% controls with a percentage readout; images and independent markings zoom together, while the details drawer stays at normal size. Type and Status fill equal-width sections of that drawer. Component photos open a centered viewer with zoom controls, wheel zoom, drag-to-pan, Escape dismissal, contained keyboard focus, and focus restoration.

Standalone report navigation uses a viewport-height workspace: project title, compact dates, and right-aligned zoom controls share one header; scene tabs stay at the bottom. The middle scene viewport supports cursor-anchored wheel zoom and middle/right-button drag panning, including scenes smaller than the viewport. Component details occupy a reserved middle column and never cover the header controls or tabs. Duplicate scene/image headings are omitted from the canvas. Right-click context suppression is limited to the scene; pointer cancellation and capture loss end panning without selecting a component.

## Visual editor

The Visual editor has an Images sidebar, central overlapping-photograph canvas, empty Selection details sidebar reserved for future elements, and independent PCB tabs at the bottom. Its top toolbar contains Add image, the photograph tools — Measure, Calibrate, Rotate, Align, Crop, Resize — a disabled Deskew placeholder, and two view-flip buttons (mirror the whole canvas horizontally/vertically). Image cards expose visibility, editable name, confirmed delete, alignment lock, independent flips, physical-layer assignment and opacity. Topmost images appear first; card ordering changes occlusion independently of canvas placement. Lock protects position and flips while comparison controls remain editable. Each PCB starts with two copper layers; count changes preserve outer-layer assignments and confirm reassignment of removed inner layers to Unassigned. Several images may share one layer. Layer tags never automatically mirror photographs.

The photograph tools are enabled only while an image is selected in the Images sidebar; Rotate, Align, Crop and Resize additionally require it to be unlocked. Measure uses a crosshair cursor with two equivalent interactions: press-drag-release, or click once and let the line follow the cursor until a second click fixes it. Its label reads px always and mm only once the PCB is calibrated (otherwise it invites calibrating). Calibrate reuses the measure interaction and opens a themed dialog asking the real span in millimetres; the resulting px/mm is stored per PCB (a shared scale — images are not rescaled) and future measurements read correct mm. Rotate shows a circular gizmo at the photograph's centre: drag its knob to rotate freely (Shift snaps to 15°), or drag a line along a feature that should be level to snap it to the nearest horizontal/vertical. Align collects four numbered markers on the moving photograph and then four matching reference points anywhere in the scene, with a magnifier loupe (~4×) near the cursor for precision; the least-squares fit (skew- and mirror-capable) is composed into the image and reports its max residual. Degenerate (collinear) points abort with a message. Crop drags a rectangle in the photograph's own axes — non-destructive and recoverable by re-cropping wider — previewed as a glued footprint with the outside dimmed. Resize drags a horizontal then a vertical reference line across known features, prompting for each real dimension (skippable per axis); when the PCB is uncalibrated the first entered dimension defines the scale instead of stretching. Starting Rotate, Align, Crop or Resize warns when existing alignments (any image carrying a warp) could break. View flips are visual-only: they mirror rendering and pointer mapping about the canvas centre, never touch the document, and reset on PCB or project change. Every tool gesture is one undo entry; Esc cancels the gesture and the tool (an open dialog swallows Esc first). Tool flows never select or move images, and the middle button keeps panning while a tool is active.

Visual editor settings open from an icon-only button aligned to the right of its tool row. The modal currently contains only the active PCB's copper-layer count; the image sidebar contains only image controls. Layer-count edits apply immediately through existing project persistence, with confirmation before assigned inner layers are removed. The dialog contains keyboard focus, closes with Escape or backdrop/Close, restores focus to its invoking button, and dismisses on workspace, PCB or project changes.

Visual editor image cards stretch across the Images sidebar with narrow outer gutters. Their grip uses pointer-based reorder with a visible destination and commits only on release; cancelling leaves order unchanged. Locked images show a closed lock with a persistent gold highlight while its accessible action remains Unlock.
